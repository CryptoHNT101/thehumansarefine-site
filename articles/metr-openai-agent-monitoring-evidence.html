28 passed, 0 failed. Exit 0.

A defect in the first version of this verifier — recorded, because it produced false results

The first run reported 5 failures. Four were false. The verifier used Get-Content -Raw, which decodes using the system codepage rather than UTF-8; on a UTF-8 file written without a BOM this produces mojibake, so a needle like 75-94% could not match 75–94%. I initially misread this as file corruption and reported it as such. Reading the raw bytes with [IO.File]::ReadAllText($path, [Text.Encoding]::UTF8) showed zero mojibake in every report file — the corruption was in the diagnostic, not the artifacts. The verifier now reads UTF-8 explicitly and carries encoding guards that fail loudly instead of reporting phantom content mismatches.

One failure in that first run was real and is fixed: the article omitted the 38-page OpenAI-redacted version.

Four prose edits were made to satisfy verbatim fidelity: "fewer than" → "less than" for the 0.2% error rate; the compaction sentence realigned to the source's own wording; the 61-page report description made explicit; the 38-page redacted version added.

Negative assertions — what the article must not say

Machine-enforced in the verifier, all passing:

  1. Must not frame METR's work as a response to Anthropic. The article states they are "contemporaneous rather than sequential."
  2. Must not claim OpenAI's fixes were verified. The article closes: "Neither METR nor this newsroom has verified that."
  3. Must not present the coverage figures as current. The article states the findings describe the system "as it stood on and before July 21, 2026" and quotes METR on not establishing current coverage.
  4. Must not use the canary or training-prohibition strings present in the source page.

Canary guard

The METR page carries a data-canary identifier and a training-prohibition notice. Both are deliberately not reproduced in the article, and the verifier asserts their absence. Content from the page is quoted for reporting only.

Outstanding uncertainties

  1. OpenAI's remediation is unverified. METR did not evaluate it; we did not either. The article says so twice.
  2. The public account is a redacted subset. OpenAI held sole discretion over redactions and METR could not describe what was removed. The 61-page report and the 38-page redacted version are not public. We cannot know what was withheld.
  3. Percentages are estimates with wide error bars, stated by METR as "substantial uncertainty in both directions."
  4. The compaction gap estimate (~10%) is partly reconstructed: METR notes the information needed to compute it precisely had not historically been logged.
  5. Five findings were not all validated in practice. METR explicitly did not test whether the "read-only" tools exploit was exploitable.
  6. No independent replication. One external team, one exercise, one lab's cooperation. No second red team has published a comparable assessment of the same system.
  7. No one from METR, Redwood or OpenAI was interviewed. Every quote is from the published post.
  8. "Open problem" framing belongs to Anthropic's paper, not METR's. Deliberately not imported into this article.
  9. Prior exercise date (March 25, 2026) is taken from METR's URL slug and index listing, not from a re-read of that page's own body.

Disputed or contested

Nothing in the article is contested by a second source, because no second source on this specific exercise exists. That is a limitation, not a strength: the article rests on a single institutional account, corroborated only by the fact that OpenAI's right of review is disclosed by METR and that METR states it endorses every finding published.
